Live verdicts

connecting to the desk…

Every line is one candidate the desk built off the live launchpad feed and then judged: the rule that fired, the sentence it fired with, and the contract address, so the coin can be looked up later and the rule argued with. Refusals are appended to data/refusals.jsonl.

A run pulls the newest mints off pump.fun, groups them by ticker, looks up the oldest coin ever minted under each name and hands it to WARDEN. The clock in the header is that run's timestamp, not your page load - when the desk stops running, the page says so instead of pretending. One verdict per ticker per 24 hours, the cooldown the rulebook already gives WARDEN, so these are new names rather than the same ones judged again.

Every run reads about a thousand fresh mints, the last forty minutes of the launchpad, and every number on this page comes off that feed or off the chain. Nothing is typed in by hand.

Why the refusals are the product

Every trading bot anyone publishes is an optimist. It scans, it enters, it shows a green candle. Nobody posts the trade their bot refused, for a boring reason: a refusal has no chart. There is nothing to screenshot.

That half is where the money was going. So this desk writes down the other side - every refusal, with the contract attached - and in a month anyone can check what those coins did and tell me the rules were wrong.

The eight, one job each

R1GRAVEYARD Indexes the dead. A coin that runs out of buyers sinks to the floor of an empty curve and stays there.
is this coin actually on the floor of an empty curve?
R2MIDWIFE Counts names, not candles. Forty nine mints of one ticker in six hours is not a market, it is production.
is someone manufacturing a wave on this ticker right now?
R3COLLECTOR Takes the original, never the clone. If it already ran, the desk is not interested.
am i about to buy the corpse, or a copy of it?
R4CLOCK Keeps the sell button locked for five minutes. The stop is the only thing that overrides it.
has the position been held long enough to close?
R5TOLL Counts the fee while you trade, and freezes new entries when the hour's fees eat the hour's profit.
is the hour's fee bill eating the hour's profit?
R6LADDER Adds to winners, and only to winners. Averaging down is banned at desk level, with no override.
is this position already in profit before i add to it?
R7UNDERTAKER The thesis has a clock. Six hours, then the position closes whether or not it might still work.
has the reason for this trade expired?
R0 · outranks all sevenWARDEN The one that says no. It runs the seven in order, then adds the question nobody else on the desk asks - and every check it owns is about the exit, none about the upside. There is no manual override: a refusal is final, and it is written down.
if i buy this, who buys it from me?

Seven rules, seven agents, one threshold file. Nothing in the code hard-codes a number - every agent reads rules.json, so all seven can be read, diffed and argued with in one screen.

What is not in it

  • execution layer. It never signs a transaction.
  • private key handling. There is no key that unlocks trading, because there is no trading.
  • wallet.
  • claimed returns. No multiples, no green portfolio screenshots.

Unknown is a no. On a fresh clone the desk cannot read holder counts without an indexed RPC, and it does not shrug and pass - it refuses.

The agent that finds coins is cheap.
The one that refuses them is the product.
